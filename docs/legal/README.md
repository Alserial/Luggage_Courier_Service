# Kargo 规则与协议草案包

> 状态：法务审核草案，禁止直接作为生产环境最终文本发布
> 草案版本：`2026-08-22-draft.1`
> 核对日期：2026-08-22
> 默认范围：中国大陆与澳大利亚之间的受控双向试点，仅限年满 18 周岁的用户

## 1. 采用什么结构

不建议为中国和澳大利亚分别复制一整套协议。推荐使用：

1. 一套统一的用户服务协议、隐私政策和平台交易规则；
2. 一份中国进出境合规附件；
3. 一份澳大利亚进出境合规附件；
4. 一份按路线组合的四阶段检查表；
5. 在每个订单中记录实际适用的规则版本和确认场景。

这种结构可以避免账号、费用、证据、争议等通用条款出现两个版本，同时允许海关、检疫、航空和申报规则按出境地与入境地分别更新。

## 3. 统一的产品边界

- 平台只提供低值、低频、低风险个人小件的信息匹配、审核辅助和履约留痕。
- 平台不是代购方、承运人、货运代理、报关行、清关机构、保险人或商品货款托管方。
- 平台的品类审核不等于海关、检疫部门、航空公司或其他主管机关批准。
- 任何一方不得要求携带人隐瞒物品、代填虚假申报、拆分规避限额或使用旅客免税额度规避货物申报。
- 有偿替他人携带的物品可能不符合“自用合理”或个人行李优惠条件；无法确认时必须申报、咨询主管机关或拒绝携带。
- 主管机关或者航空公司的决定优先。需要货物申报、许可、检疫证明或专业运输的物品不进入本平台普通旅客行李流程。

## 5. 推荐的版本与同意记录

每次需要确认规则时，后端应至少保存：

```text
userOpenid
documentKey
documentVersion
documentHash
scene
orderId/requestId/tripId（按场景）
acceptedAt（服务端时间）
operationId
```

不得预先勾选。收费、退款、平台责任边界、海关申报、证据使用、争议处理等重大条款应以加粗、独立卡片或二次确认方式提示。

## 6. 发布门槛

草案只有在以下事项完成后才能转为正式版本：

1. 运营主体与中澳业务模式由中国和澳大利亚执业律师复核；
2. 确认有偿替他人携带物品在试点口岸、航司和用户身份下的申报路径，以及该模式是否构成受监管运输、代理、零工或其他经营活动；
3. 确认携带人在中国和澳大利亚提供有偿服务所需的身份、签证、工作权、税务和保险条件；
4. 完成微信小程序隐私保护指引和个人信息清单配置；
5. 确认真实支付、退款、结算、发票与税务方案；
6. 将规则版本确认和后端留痕接入关键流程；
7. 对中→澳、澳→中各完成一次三账号真机全链路测试；
8. 法务签署最终版本并替换全部占位符。
9. 面向英文用户开放前完成专业英文翻译及澳大利亚法律复核；中英文不一致时的解释规则不得减损强制法定权利。
10. 关闭 `13-bilateral-legal-risk-register.md` 中与拟上线功能有关的全部 P0 停止线，并为 P1 风险指定负责人和验收证据。
