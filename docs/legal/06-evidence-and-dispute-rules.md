# Kargo 证据与争议处理规则（法务审核草案）

> 草案版本：`2026-08-22-draft.1`

## 1. 目的和边界

本规则用于平台内部的履约核对、订单状态、账号措施和服务费处理。平台的争议决定不是法院、仲裁机构、海关、警方、保险人或行政机关的最终法律责任认定。

平台不得用本规则排除用户依法投诉、举报、调解、仲裁或诉讼的权利。

## 2. 证据基本规则

1. 证据记录只追加，不覆盖原记录。
2. 证据由后端记录订单、提交人、类型、文件、可见范围、时间、操作编号和必要元数据。
3. 平台应尽量保存原文件或不可变快照、内容哈希和审计记录。
4. 用户应提交真实、完整、与订单有关且合法取得的证据，不得伪造、剪辑误导或侵犯无关第三人权益。
5. 证据是否充分应结合来源、完整性、时间、关联性、双方陈述和其他记录综合判断，不以单一截图自动定责。

## 3. 证据类型

| 类型 | 用途 | 通常提交人 |
|---|---|---|
| `item_photo` | 发布及交接前物品、数量、包装和状态 | 需求方/双方 |
| `handover_qr_scan` | 交接码和交接动作确认 | 系统/双方 |
| `in_app_chat` | 与订单有关的不可变聊天快照 | 系统 |
| `payment_record` | 服务费支付、退款和状态记录 | 系统 |
| `flight_record` | 航班、行程或变更证明 | 携带人 |
| `customs_or_airline_proof` | 查验、拒载、延误、税费、扣留或退运证明 | 双方 |
| `delivery_photo_or_video` | 到达后的物品状态和交付 | 携带人/需求方 |
| `mutual_confirmation` | 双方最终确认或系统确认记录 | 双方/系统 |

## 4. 关键节点证据

- 发布需求：1 至 6 张真实物品照片；
- 交接：新的物品状态照片、交接检查项和交接码；
- 支付：后端或支付服务商形成的服务费记录；
- 送达：目的地照片或视频；
- 完成：需求方确认及双方确认记录；
- 异常：航司、机场、海关、检疫或其他主管机关能够提供的文件和站内通知；
- 争议：至少一项与争议理由直接相关的证据。

## 5. 可见范围

| 范围 | 可查看者 |
|---|---|
| `both_parties` | 需求方、携带人、授权管理员 |
| `requester_only` | 需求方、授权管理员 |
| `traveller_only` | 携带人、授权管理员 |
| `admin_only` | 授权管理员/审核员 |

身份证件、完整登机材料、支付敏感字段和执法机关文件默认不得公开，应按必要性设置受限范围并进行脱敏。

## 6. 发起争议

1. 订单参与方可以在 `completed`、`cancelled` 或 `refunded` 之前，对物品、交接、延误、送达、费用、税费或异常处理发起争议。
2. 同一订单同时只允许一个活动争议。
3. 申请应包括争议类型、事实说明、具体请求和至少一个证据编号。
4. 争议发起后，订单进入 `disputed`，普通履约状态转换和结算暂停。
5. 完成后的投诉依法继续受理，但是否重新开启平台订单争议，应结合证据、适用法律和保存期限人工判断。

## 7. 双方陈述与举证

1. 平台应向双方提供合理陈述和补充证据机会。
2. 需求方通常应证明物品内容、价值、交接前状态和损失主张。
3. 携带人通常应证明本人完成开箱核验、依法申报、按约保管、异常通知和送达情况。
4. 平台应提供其控制范围内的订单状态、聊天快照、支付和审计记录，不得把只能由平台控制的证据责任不合理转嫁给用户。
5. 一方拒不提交其控制的关键材料，可以作为综合判断因素，但不得自动认定全部责任。

## 8. 审核流程

建议的试点服务目标如下，正式上线前应确认人员和时限：

1. 收到完整申请后 3 个工作日内完成初步检查；
2. 需要补证时一次性说明主要缺项，并给予通常不少于 5 个自然日的补充时间；
3. 材料完整后通常在 10 个工作日内作出平台处理；复杂、跨境或等待官方文件的，可以延长并说明原因；
4. 仅由自动系统作出不利决定时，用户可要求人工复核；
5. 审核人员存在利益冲突的，应回避。

以上为内部服务目标，不得解释为对法院、海关、航空公司或支付服务商处理时限的保证。

## 9. 平台处理选项

授权管理员可根据证据作出：

- `refund`：处理平台记录的服务费退款；
- `complete`：确认平台履约流程完成；
- `cancel_order`：取消订单；
- `keep_in_dispute`：要求补证或维持争议状态。

决定必须记录管理员、理由、审阅证据、订单前后状态、支付影响和服务端时间。商品价值损害赔偿不自动由平台服务费退款代替，也不应在没有保险或专项保障时承诺平台全额赔付。

## 10. 判断因素

平台可综合考虑：

- 物品是否属于正面清单并与描述一致；
- 是否完成开箱核验、申报和航空规则检查；
- 物品交接前后和送达时的可验证状态；
- 双方是否及时站内通知和减少损失；
- 官方或航空公司文件；
- 是否存在故意隐瞒、虚假证据、擅自处置或重大过失；
- 平台系统或审核是否存在错误；
- 强制适用的消费者和格式条款规则。

不得仅因某方角色是需求方或携带人而预设其必然承担全部责任。

## 11. 申诉

1. 用户可在收到平台决定后 `[建议：7个自然日]` 内申请一次内部复核，并说明新事实、程序问题或规则适用错误。
2. 原决定人员原则上不担任复核决定人。
3. 平台应提供人工复核并告知结果和主要理由。
4. 内部申诉不妨碍用户向监管机关、调解机构、仲裁机构或法院寻求救济。

## 12. 保存和隐私

争议材料按隐私政策保存。平台应限制管理员访问、记录查看操作并避免在决定书中披露无关个人信息。依法需要提供给主管机关或法院的，按有效程序提供。
