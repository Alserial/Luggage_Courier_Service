# Kargo 平台交易与履约规则（法务审核草案）

> 草案版本：`2026-08-22-draft.1`
> 适用于中澳双向受控 MVP；与用户服务协议及路线附件共同适用

## 1. 基本原则

1. 每个订单必须同时满足平台规则、出境地规则、入境地规则、经停地规则和航空公司规则。
2. 平台只撮合低值、低频、低风险个人小件，不撮合代购、商业批量运输、报关、清关或商品货款支付。
3. 需求方对物品信息和合法来源负责；携带人对本人行李内容、航空安全和边境申报负责；平台对自身撮合、记录、审核和数据处理行为依法负责。
4. 平台内确认不能替代政府许可、申报、检疫或航空公司批准。

## 2. 交易角色

- **需求方**：发布希望由他人顺路携带的物品需求并支付约定服务费的用户。
- **携带人**：发布本人真实行程、检查物品并决定是否接受帮带的用户。
- **平台**：提供信息、审核辅助、匹配、报价、订单状态、证据、沟通和争议流程的运营方。
- **审核员/管理员**：依权限处理品类、行程、内容、投诉和争议，不得绕过后端审计。

任何用户都不得暗示平台、需求方或携带人与海关、检疫、航空公司存在代理、授权或保证关系。

## 3. 发布需求

需求方提交需求时必须：

1. 使用平台正面清单中的品类；
2. 填写真实具体的物品名称，不使用“日用品”“礼物”等无法识别内容的笼统描述；
3. 填写数量、申报价值、重量、交接城市、交付城市和最晚日期；
4. 上传 1 至 6 张能够识别实物、包装、数量和标签的照片；
5. 披露是否含电池、磁性部件、液体、粉末、喷雾、动植物成分或其他受监管成分；
6. 确认物品来源合法并接受开箱核对；
7. 确认平台上限不是海关免税额度或合法性判断；
8. 接受物品与申报规则的当前版本。

需求提交后进入审核。平台可批准、拒绝或要求补充材料。审核未通过的需求不得匹配或生成报价。

## 4. 发布行程

携带人提交行程时必须：

1. 填写真实出发地、目的地、出发和到达日期；
2. 仅填写本人实际乘坐的行程；
3. 如实填写可用重量和愿意接受的正面清单品类；
4. 在订单确认前按平台要求提供航班或行程核验材料；
5. 了解本人需要知道并控制行李全部内容；
6. 不发布“什么都能带”“免税包过”“保证清关”等承诺；
7. 接受出境地、入境地和航空规则附件的当前版本。

缺少航班号或核验材料的行程可以进入人工审核，但不得在核验通过前生成真实报价或订单。

## 5. 匹配

1. 平台可依据路线、日期、品类、容量和审核状态生成候选匹配及解释性评分。
2. 匹配结果仅供双方判断，不表示平台确认物品能合法出境、入境或登机。
3. 需求方和携带人必须在报价前再次核对物品、路线和日期。
4. 平台发现规则变化、品类风险、行程异常或数据不一致时，可移除匹配并记录理由。

## 6. 报价

1. 报价人必须是对应行程的携带人，且不得对自己的需求报价。
2. 报价只包括帮带服务费，不包括商品货款、关税、GST、检疫处理费、保险或其他未明确费用。
3. 报价应列明交接时间、地点和特殊条件，不得要求站外支付或规避平台证据。
4. 当前 MVP 帮带服务费报价上限为 CNY 500；该上限是平台风控限制，不代表法定限额。
5. 报价有效期为 48 小时，逾期、需求或行程修改、审核状态变化时自动失效或取消。

## 7. 接受报价与订单成立

1. 需求方应在接受报价前查看物品、路线、金额、条件、取消退款、税费承担、证据要求和中澳路线附件。
2. 需求方主动确认后，订单成立并进入 `pending_payment`。
3. 平台应记录接受人的身份、报价、规则版本、服务端时间和操作编号。
4. 接受报价后，其他待处理报价应按平台规则失效或拒绝。
5. 物品、路线、行程日期或金额发生重大变化的，应取消原订单并重新审核，不得仅通过聊天私下变更。

## 8. 订单状态

订单必须使用以下明确状态并保留转换审计：

| 状态 | 含义 |
|---|---|
| `draft` | 尚未提交 |
| `pending_review` | 等待审核 |
| `approved` | 审核通过 |
| `pending_payment` | 已接受报价，等待服务费确认 |
| `paid_locked` | 服务费提供方/Mock 记录显示已锁定 |
| `item_handed_to_carrier` | 已完成交接证据和确认 |
| `in_transit` | 携带人确认进入在途 |
| `arrived` | 已抵达目的地 |
| `delivered` | 已交付，等待需求方确认 |
| `completed` | 双方履约流程完成 |
| `disputed` | 争议处理中 |
| `cancelled` | 已取消 |
| `refunded` | 平台记录的服务费已退款 |

状态变化必须由有权限的后端函数根据角色、前置状态和证据执行，前端展示或聊天表述不能改变订单状态。

## 9. 交接

交接前双方必须：

- 核对物品名称、数量、型号、成分、价值、重量和照片；
- 允许携带人开箱检查，不交接密封且内容无法确认的包装；
- 检查是否出现电池、液体、粉末、食品、药品、动植物成分等未披露风险；
- 重新检查航空公司和两国边境要求；
- 完成物品状态照片、交接码和双方确认；
- 确认税费、异常、取消和争议规则。

任一方发现信息不一致、无法确认合法性或需要许可而未取得文件，应拒绝交接并在平台留痕。

## 10. 在途、抵达与送达

1. 携带人应妥善保管物品，不得擅自使用、拆换、转交、出售或设置担保。
2. 航班变更、行李延误、安检拒载、边境查验、税费、扣留、退运或损坏应及时在平台通知。
3. 对官方或航空异常，应上传可取得的凭证，但不得拍摄或公开依法禁止拍摄的执法区域或文件。
4. 抵达后，携带人应在约定地点完成送达并上传送达照片或视频。
5. 需求方核验后确认完成；有问题的，应在确认完成前发起争议。

## 11. 取消与异常

1. `pending_payment` 阶段可以按规则取消，无已支付服务费可退。
2. `paid_locked` 且尚未交接时，原则上可以取消并处理平台记录的服务费退款，但实际支付启用后以支付服务商规则为准。
3. 交接后取消必须由双方协商或进入争议审核，不自动认定任何一方责任。
4. 因监管、安检或航空公司决定无法履约时，双方应优先保护人身和合规安全，停止携带并保存证据。
5. 退运、销毁、处理或税费由谁承担，应结合物品信息是否真实、双方过错、官方决定和订单约定，不得一律转嫁给消费者或无过错方。

## 12. 完成与后续记录

1. 需求方确认收货后生成 `mutual_confirmation` 证据并进入 `completed`。
2. 完成前有有效争议的，不得继续普通状态流转。
3. 完成后订单、服务费、证据和审计记录按隐私政策保存；普通平台争议入口可以关闭，但不影响用户依法投诉、仲裁或诉讼。

## 13. 禁止行为

- 发布、携带禁限物品或需要专业运输的物品；
- 对物品名称、成分、数量、价值、来源或用途作虚假陈述；
- 盲带、夹带、藏匿、拆分、伪装或教唆虚假申报；
- 利用不同旅客免税额度组织批量商业运输；
- 站外支付商品货款或服务费以逃避规则；
- 伪造航班、购买、支付、海关、航空或交接证据；
- 侵犯知识产权、隐私、肖像、名誉或其他合法权益；
- 欺诈、骚扰、威胁、洗钱、走私或其他违法行为。

## 14. 平台处置与申诉

平台可根据风险程度采取警示、补充材料、人工审核、拒绝发布、取消匹配、限制订单、隐藏内容、暂停功能或关闭账号。除紧急情形外，应说明事实、理由和规则依据并提供申诉入口。用户可要求人工复核。
