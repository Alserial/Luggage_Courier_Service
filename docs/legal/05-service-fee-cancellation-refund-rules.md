# Kargo 服务费、取消与退款规则（法务审核草案）

> 草案版本：`2026-08-22-draft.1`
> 重要：当前代码仅实现 Mock 服务费记录，不代表真实资金处理

## 1. 费用类型

| 费用 | 当前 MVP | 说明 |
|---|---:|---|
| 帮带服务费 | 支持报价和 Mock 记录 | 携带人对帮带服务的报价 |
| 平台服务费 | 支持后端金额计算和 Mock 记录 | 当前计算为帮带服务费的 8%，向上取整到人民币元；正式标准待公示 |
| 商品货款 | 不支持 | 平台不代购、不托管、不代收 |
| 关税、GST及其他税费 | 不代收 | 由主管机关决定，责任按本规则和双方过错处理 |
| 检疫、处理、仓储、退运或销毁费用 | 不代收 | 以主管机关/服务方决定为准 |
| 保险费或赔偿基金 | 未提供 | 未明确上线前不得宣传有保险或全额赔付 |

## 2. 报价与金额展示

1. 携带人报价仅指帮带服务费，当前上限 CNY 500。
2. 平台应在接受报价和支付前分别列出帮带服务费、平台服务费和合计金额。
3. 未单独列明的费用不得通过聊天或交接现场强制收取。
4. 金额、币种、收费主体、退款路径和发票方式应在真实支付启用前明确公示。

## 3. Mock 阶段

1. `payment-confirm-mock` 只生成测试支付记录、支付证据和订单状态变化。
2. “Mock 服务费已锁定”不代表用户账户发生真实扣款，也不代表平台或任何支付机构实际托管资金。
3. Mock 阶段不得向用户收取真实服务费，不得通过私人转账模拟平台支付。
4. 演示页面和测试记录必须持续显示“Mock/演示/未真实扣款”。

## 4. 真实支付上线条件

启用真实支付前必须：

- 确定合规支付服务商、商户主体和服务协议；
- 确认是否允许延迟结算、分账、锁定和退款；
- 后端创建支付、校验金额和签名、处理回调与幂等；
- 明确支付失败、取消、退款、拒付和结算规则；
- 公示支付服务商及其个人信息处理；
- 明确发票、税务和客服责任；
- 完成法务、财务和三账号真机验收。

前端不得保存商户密钥、证书或自行认定支付成功。

## 5. 取消与默认处理

| 订单阶段 | 谁可申请 | 默认处理 | 证据/审核 |
|---|---|---|---|
| `pending_payment` | 任一参与方 | 取消订单；无已支付服务费可退 | 必须填写原因 |
| `paid_locked`、交接前 | 任一参与方 | 原则上取消并退平台记录的服务费 | 检查支付状态和未交接证据 |
| `item_handed_to_carrier` | 任一参与方 | 不自动取消/退款，协商或争议 | 交接、聊天和物品证据 |
| `in_transit` / `arrived` | 任一参与方 | 进入协商或争议 | 航班、官方异常、沟通证据 |
| `delivered` | 任一参与方 | 不自动退款，需求方确认或争议 | 送达和物品状态证据 |
| `completed` | 依法投诉或平台例外复核 | 无普通自动退款 | 法律权利不受影响 |
| `disputed` | 管理员/审核员按流程 | 退款、完成、取消或继续补证 | 必须关联决定和证据 |
| `refunded` | 不重复退款 | 终局退款记录 | 保留支付和审计记录 |

## 6. 服务费退款

1. 退款对象仅限平台记录的帮带服务费和平台服务费，不包括商品货款、关税、GST或线下支付。
2. 真实支付启用后，退款以原支付路径和支付服务商状态为准。
3. 平台不得仅以前端按钮或聊天承诺认定退款成功；必须由后端/provider 回调形成支付、证据和审计记录。
4. 因重复支付、系统错误或平台错误收取的金额，应依法及时原路退回。
5. 交接后退款应考虑双方过错、履约程度、物品状态、官方决定及可验证证据，不采用“一律不退”或“一律仅退款”等不公平规则。
6. 退款决定不得排除用户依法投诉、调解、仲裁或诉讼的权利。

## 7. 税费和边境处置费用

1. 订单默认由需求方承担因真实、完整申报而正常产生的进口税费，但主管机关可能要求携带人现场缴纳；双方应保留凭证并按订单规则结算。
2. 因需求方隐瞒、低报、错报、提供假材料或物品与描述不一致产生的费用和损失，由需求方依法承担相应责任。
3. 因携带人擅自不申报、虚假申报、混入其他物品、违反航司要求或未按约定保管产生的费用和损失，由携带人依法承担相应责任。
4. 平台审核或系统错误对损失有因果关系的，平台依法承担与过错相适应的责任。
5. 海关、检疫或航空公司对缴费主体和处理方式的决定优先，双方之间的内部约定不得阻碍现场依法处置。

## 8. 结算

1. Mock 阶段不发生真实结算或放款。
2. 真实结算只能由支付服务商回调、后台受权函数或经授权的人工流程执行。
3. 正常结算候选条件包括订单 `completed`、没有活动争议、必要证据完整以及风险审核通过。
4. 争议、监管扣留、支付异常或证据不一致时，可以依法依约暂停结算，但应告知理由和申诉路径。

## 9. 对账、记录和投诉

平台应向用户展示订单号、费用明细、支付/退款状态和必要的提供方交易号，并保留可审计记录。金额或状态有误时，用户可通过 `[待填写：支付投诉入口]` 提交；平台目标响应时限为 `[待填写]`。
